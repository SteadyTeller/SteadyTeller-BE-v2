# 2차 1·2·6번 연결 — 미확정 계약

## 최종 담당 구분

- 서희: 1 가용시간 설정, 2 타이머/결과 입력, 6 목표일 도달 안내 및 계속/종료 연결
- 진우: 3 기록/통계, 4 실패 항목 처리, 7 확정 태스크 관리
- 정현: 5 재배치/재계획

## 1번 현재 구현

기존 회원 공통 Availability CRUD를 FE 목표 생성/수정 화면에 연결.
요일별 시간 입력과 15분 단위 드래그 슬라이더를 제공한다.
시간대는 추가/삭제 버튼으로 즉시 저장되며 목표 저장과 별개라고 화면에 안내.
회원 공통 재사용은 임시 기준이며 목표별 저장 여부는 팀 합의 필요.
기존 dailyStudyHours/availableDays는 기존 스케줄링 호환을 위해 유지.
실제 시간대 기반 최초 배치의 담당과 데이터 계약은 팀에서 확정해야 함.

## 6번 현재 구현

GET /api/v1/goals/{goalId}/deadline: JWT 회원의 본인 목표만 조회.
현재 targetDate는 날짜이므로 한국 시간 해당 날짜 종료 후 도달로 판단.
확정 태스크 중 미배정 또는 미완료 배정 항목이 남은 태스크를 조회.
FE에서 목표일 경과 시 남은 학습 목록 표시.
계속/종료 쓰기 API는 아직 없으며 정현의 재배치/예상 종료일 계약과
진우의 제외/분할 상태 계약 확인 후 연결. 자동 상태 변경·자동 연장 없음.
확정 태스크 제외/분할 상태 도입 시 조회 필터도 그 계약에 맞춰 변경 필요.

기존 회원/JWT, ScheduleItem 시작·완료 API와 통계는 유지한다.
FE `feat/9-study-timer`에 타이머와 로컬 결과 초안을 구현했다.
이 문서는 구현 완료 계약이 아니라 팀 합의용 초안이다.

## 현재 동작

- 개별 ScheduleItem 시작 성공 후 타이머 시작
- 일시정지·재개·종료, 예정 시간 도달 시 화면 알림
- 회원별 브라우저 저장소에 진행 타이머 복원 정보 보관
- 종료 시 실제 분, 완료/실패, 실패 이유, 학습한 내용·남은 내용 입력
- 완료는 기존 완료 API 사용
- 실제 시간·실패 결과는 로컬 미전송 초안만 보관
- 실패 상태 변경·DB 기록·실패 통계·AI·재배치는 아직 연결하지 않음
- 다른 기기 복원, 앱 종료 후 알림은 지원하지 않음

## 진우 담당에 제안하는 결과 저장 계약

입력: attemptId(UUID), scheduleItemId, actualSeconds(정수), outcome(COMPLETED/FAILED),
failureReasonCode, failureReasonDetail, learnedContent, remainingContent.
현재 FE 초안의 actualMinutes/한국어 이유는 확정 계약으로 변환할 예정.

memberId는 JWT, goalId/learningTaskId/예정 시간은 서버 조회.
기록 당시 예정 날짜·분량을 스냅샷으로 저장해 재배치와 통계를 분리.
attemptId에는 회원 범위 DB UNIQUE를 적용하고 같은 식별값의 다른 내용은 충돌 처리.
재시도는 새 attemptId를 사용하며 기존 결과는 유지.

## 담당자 합의 필요

- 실패 상태 및 재시작 시 상태 전이: 스케줄링 담당
- 미룰 때 scheduleItemId 유지 여부: 스케줄링 담당
- 수행 기록 저장과 상태 변경 함수를 같은 트랜잭션에 연결
- 기록 수정/완료 취소 정책과 시도 기준 통계 분모
- 회원 공통 Availability와 목표별 시간대의 적용 기준

## 남은 검증

- 브라우저 시작→일시정지→새로고침→종료
- 예정 시간 도달 알림
- 인증 만료 후 같은 회원 재로그인 시 초안 복원
- 다른 회원·다른 목표로 이동 시 잘못된 항목 완료 방지
- 저장 API 합의 후 권한·중복 요청·원자성 테스트
- 서버에 기록 저장 후 재배치·통계 통합 테스트

로컬 저장 데이터는 공유 기기에 남을 수 있으므로 배포 전에 삭제 UI와 보관 정책을 정한다.
현재 상태는 개발용이며 2차 MVP 배포 완료 상태가 아니다.
